## 2026-10-25（二）v0.1.0 实现落地（邮件库 + 基础库下沉）

**用户原话**

> 要尽可能先参考其他Rust项目实现功能，并尽可能的复用已有的方法和库以及要提取可公用的方法到DH.RustBase，但首先要先参考把全局用户指令功能完善。

**实现（`pek-rmail` v0.1.0）**

| 模块 | 内容 |
|---|---|
| `settings` | `MailSettings`/`MailData`（PascalCase 与 C# 对齐）、`find_default`/`find_all_enabled`/`find_by_code`/`find_by_suffix`/`route_for`、`MailSettingsFile`（TomlConfig + `[[Data]]` 数组表保存/热加载） |
| `message` | `EmailBox`、`MailMessage`（From/ReplyTo/优先级/自定义头）、`Attachment`（文件/内存/Reader）、`MailPriority` |
| `sender` | `EmailSender` trait、`SmtpEmailSender`（lettre + rustls + ring）、`NullEmailSender` |
| `queue` | `MailQueueProvider`（Condvar 入队即唤醒）、`MailQueueService`、`MailQueueManager`（后台线程，幂等启停） |
| `mailer` | `Mailer`（配置 + 发送 + 热加载 + 指定账号/后缀路由/临时账号/后台线程发送） |

**C# 对齐**：多账号默认优先 + 失败轮换（聚合错误）、`EmailBox` 多收件人/抄送/密送/HTML、附件、邮箱后缀路由、
发送队列、临时 SMTP 参数发送（`send_temporary`，含 fallback）。

**下沉到 `DH.RustBase`**

- `text::is_email` / `text::email_suffix` / `text::split_mail_addresses`（对齐 C# `ValidFormatHelper.IsEmail` / `MailHelper.GetEmailSuffix` / `PaserMailAddress`）；
- `config::TomlConfig::save_with_arrays`（数组表同步，保留注释与排版）——后续所有含 `[[数组表]]` 的配置可复用；
- 文档：dhrust README 增加 `text` 模块与 TOML 数组表说明。

**有意差异**

- 库不引入异步运行时：同步 API + `Mailer::send_box_async` 后台线程；
- 附件文件名由 lettre 统一按 RFC 2231/UTF-8 编码（C# 版为 GB18030 + RFC2047 手工处理）；
- 队列空闲改为 `Condvar` 等待（入队立即唤醒），空闲零周期开销；
- `UseDefaultCredentials=true` 时不做 SMTP AUTH；`Domain` 字段保留但不参与认证（Windows 域场景在 Rust 侧无对应实现）。

**验证**

- `cargo test`：10 项集成测试 + 4 项文档测试全绿（假 SMTP 服务器覆盖 HTML/附件/Bcc/fallback/队列/配置回写/Mailer 配置链路）；
- `cargo clippy --all-targets`：零告警；
- `cargo zigbuild --target x86_64-unknown-linux-musl --lib`：通过（可 musl 交叉）；
- `DH.RustBase`：默认 264 项 + `--features toml` 279 项全绿，clippy 零告警。

1. 先装备接续基建：`tools/continuity/*`、`.github/copilot-instructions.md`、`docs/*`、`.vscode/tasks.json`，并运行用户级指令自检。

3. 能力对齐 C#：`MailSettings`/`MailData` 多账号（默认优先 + 失败轮换）、`EmailBox`（多收件人/抄送/密送/HTML/附件）、物理文件与内存附件、邮箱后缀路由、发送队列（后台线程 + 间隔）。

## 2026-10-25（四）第二轮全量审计与性能分析

**用户原话**

> 接下来还有什么要继续的么？或者是否还有其他的可以提取到DH.RustBase，以及还要再做一次全量审计，也帮我分析一下性能上这两个项目是否能优化

**结论**

1. 基线保持：Mail 2 单元 + 10 端到端 + 4 文档；SMS 4 单元 + 14 端到端 + 2 文档；DH `--features toml` 284 passed（1 ignored）；三仓 clippy 零告警；Mail/SMS musl 通过。
2. 性能实测（Windows/release/本机）：Mail 队列 161ns、消息构建约 0.4µs、10 账号配置快照 2.5µs；SMS `extend_map` 1.4~1.7µs/次（单次发送 6~8 次）、1000 个手机号拆分约 1.6~1.8ms、`create_client` 2~3µs；HTTP offthread 比直接调用多约 0.2ms/次尝试。
3. 主要优化方向：SMS ExtendData 每次 send 只解析一次、create_client 去掉无用 settings 克隆、手机号 HashSet 去重；Mail fallback 路径单次快照、附件/队列上限；两项目 `reload_if_changed` 约 49µs，勿放在每封/每条路径。
4. 新下沉候选（P1）：`web::form_encode`、`http_client::blocking_request_auto`；P2：`RetryPolicy`、`json`、`times`、`text`、`io::read_file_limited`、`BlockingQueue`、`SecretString`。
5. 本轮只做审计、测量与文档，未改运行时代码；临时性能探针已删除。

**报告**：`docs/审计报告-第二轮性能-2026-10-25.md`；跨项目对照：`DH.RustBase/docs/审计报告-第二轮性能与下沉-2026-10-25.md`。
