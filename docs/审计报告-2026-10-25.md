## 3. 发现（按优先级）

| 级别 | 位置 | 问题 | 影响 | 建议 |
|---|---|---|---|---|
| **P1** | `src/sender/smtp.rs:179` | 附件通过 `Attachment::read()` 整文件读入内存，无大小上限 | 大附件导致内存峰值/OOM | 增加 `max_attachment_bytes`（默认如 25MB）并返回 `MailError::Attachment`；超限直接失败 |
| **P1** | `src/queue.rs:25` | `MailQueueProvider` 无队列上限 | 突发入队可无限增长 | 增加 `max_queue`，满时 `try_enqueue` 返回错误/指标；或提供 `enqueue_timeout` |
| **P1** | `src/settings.rs:59-61` | `MailData` 派生 `Debug`，包含 `password`；`MailSettings` 同样 | `{:?}` 日志可能泄露 SMTP 密码 | 手写 `Debug`，`password` 输出 `***`；长期可下沉 `dhrust::secret::SecretString` |
| P2 | `src/queue.rs:291` | `Drop` 调 `stop()` 会 `join`，最坏等一次发送超时（30s） | 进程退出/重建管理器可能阻塞 | 提供 `stop_timeout(Duration)`；或文档明确退出延迟 |
| P2 | `src/mailer.rs:165` | `send_box_routed` 只看第一个收件人的后缀 | 多收件人不同后缀时路由不符合直觉 | 文档写明；或仅当所有收件人同后缀时自动路由，否则走默认 |
| P2 | `src/sender/smtp.rs:61` | `settings_snapshot` 锁毒化时回退 `MailSettings::default()` | 静默丢配置，表现为“无可用账号” | 用 `poisoned.into_inner()` 并 `warn!` 一次 |
| P2 | `src/settings.rs:230` | `socket_option` 每次发送对非法 `SecureSocketOption` 打 warn | 配置错时每次发送刷日志 | 加载时校验一次并缓存结果（或只在 `MailSettingsFile` 加载时提示） |
| P2 | `src/sender/smtp.rs:193` | 每次发送新建 SMTP/TLS 连接，无连接池 | 高频发送握手开销大（与 C# 一致） | 低优先级；如吞吐成为问题再评估连接复用 |
| P3 | `src/queue.rs:275` | 未启动时 `stop()` 也会打印“邮件发送队列已停止” | 日志误导 | 仅 `running=true` 时打印 |
| P3 | `src/sender/smtp.rs:323` | `parse_mailbox` 用 `rfind('<')` + `ends_with('>')` 解析显示名 | 极端显示名（含 `<`/`>`）解析不完整 | 使用 lettre `Mailbox` 的 `FromStr` 或明确文档限制 |
| P3 | `src/queue.rs:69` | `dequeue_timeout_while` 持锁调用 `should_stop` 闭包 | 闭包若反向获取同一锁会死锁 | 文档约束（当前仅读原子变量） |
| P3 | `src/mailer.rs:49` | `with_settings` 无文件句柄，`save_settings` 只更新内存 | 调用方可能误以为已落盘 | 文档已说明；可增加 `is_persistent()` |

## 4. 测试缺口

1. 大附件（超过上限/接近上限）行为；
2. 队列上限/背压；
3. `Drop`/`stop` 在发送中的退出时延；
4. 热加载与发送并发（配置替换时账号切换）；
5. 非法 `SecureSocketOption` 的日志频次；
6. 真实 SMTP 服务商互操作（可选，需外部凭据）。

## 6. 建议

1. **先做安全与 P1**：Debug 脱敏、附件上限、队列上限；
2. **再抽 `TomlConfigStore<T>`**：与 Pek.RSms 一起切换，避免只改一边；
3. **最后补测试**：大附件/队列上限/停止时延/热加载并发；
4. 不急于做 SMTP 连接池：当前发送频率低，且 C# 也是每次新建连接。
